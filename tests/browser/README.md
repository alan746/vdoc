# Real-browser preview regression

Run `npx vite --config tests/browser/vite.config.ts`, then open
http://localhost:5174/tests/browser/preview-page-breaks.html in a browser.
The page mounts the production preview dialog and iframe renderer with real
Paged.js, using HTML generated by the editor's actual extensions. No document
is saved to the user's library.

The title and `#result[data-result]` report PASS/FAIL. Assertions require exactly
three nonempty `.pagedjs_page_content` elements, ordered text, matching header
and Go to page options, a passing `previewPageBreakMismatch` audit, and enabled
printing. Before the fix this fixture produced `Page one`, `Page two`, an empty
page, and `Page three`. The inline paragraph styles from the editor are essential
to reproducing Paged.js 0.4.3's break-after propagation bug.

Select pages 2 and 3 to check navigation. Click **Print / Save PDF** to exercise
the production snapshot and local PDF renderer. When local Chrome is available,
the test server also saves the exact PDF response to
`tmp/preview-page-breaks/printed.pdf` (gitignored). Check that it contains three
pages with the same text and page numbers, and visually inspect rendered pages.
The capture wrapper uses the existing PDF handler's render dependency; production
code does not write this test artifact. Stop the test server afterward.

This test needs browser layout and is intentionally separate from the jsdom
Vitest suite. `npm test -- tests/preview-page-breaks.test.ts` covers the CSS
cascade and boundary audits; it cannot validate physical pagination.
