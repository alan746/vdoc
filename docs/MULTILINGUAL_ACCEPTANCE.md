## 对照口径

- Google Docs 可选择文档语言，并有音译输入、虚拟键盘和手写输入入口；VDoc 当前仍依赖系统输入法，已补文档语言设置，但仍没有内置输入工具。[官方说明](https://support.google.com/docs/answer/187189?hl=en-IN)
- Google Docs 有段落方向和表格列顺序方向控制。VDoc 本轮补齐段落方向参数及菜单，表格列顺序 RTL 仍缺失；单元格内 RTL 文本不是整张表格列顺序 RTL。[官方说明](https://support.google.com/docs/answer/65166?hl=en)
- Google 官方拼写／语法说明列出英、西、法、德、葡、意六种语言，不能假定所有语言功能都完全一致。VDoc 只有浏览器拼写开关，没有独立语言词典、语法建议或个人词典。[官方说明](https://support.google.com/docs/answer/57859?hl=en)
- 文档翻译属于 Google Docs 的单人能力，但需要服务端能力；VDoc 当前本地无模型范围未实现，也未在本轮接入云翻译。

## 本轮修复与新增

1. 查找采用 NFC 规范等价匹配，但不改变原文编码；保存仍精确保留原始字符串。归一化后的命中映射回原文 UTF-16 偏移，避免替换错位。
2. 查找命中必须位于完整字素簇边界，不再单独命中家庭 emoji、肤色 emoji、国旗或组合重音的部分。显式 API 文字范围也拒绝从字符中间切开。
3. 全词匹配改用浏览器 Unicode 词边界，补齐无空格日语、泰语的已测用例。它不是所有语言的人工词法标注，也不保证与 Google Docs 计数一致。
4. 状态栏、选区字符数使用字素簇，而非 UTF-16 长度。家庭 emoji 算 1 个字符；分隔开的区域指示符不会因去空格而错误合成一个国旗。按文档节点缓存统计，编辑不必重复分割全部未变段落。
5. paragraph.style 新增 direction=auto/ltr/rtl；Format 菜单提供自动、从左到右、从右到左。JSON 保留方向，HTML 输出 dir；明确 ltr/rtl 在 DOCX 使用双向段落设置并可恢复。Word 实际版式和自动方向导出后的视觉效果仍需实机验证。

Unicode 处理依赖现代浏览器的 Intl.Segmenter。分词／字素规则受运行时 Unicode 数据版本影响；本轮在当前 Node/jsdom 和内置浏览器验证，旧浏览器兼容没有通过。[API 说明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter)
